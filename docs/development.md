# Development

How the repository is organised and the conventions it follows. The design and
the reasoning behind it are in [design.md](design.md); deployment is in
[deploy/README.md](../deploy/README.md).

## Conventions


- **Everything in the repository is written in English:** code, identifiers, comments, commit messages, docs, UI text.
- Follow the "Data and ML rules" in `docs/design.md`; they are mandatory.
- Never click-test against real data: reviews are append-only. Use the preview database (below).
- Postgres is reached via `127.0.0.1`, not `localhost` (which hangs on the Windows dev machine).
- All API routes live under `/api`. Line endings are LF (`.gitattributes`).

## Repository

- `web/` – SvelteKit SPA (`vite.config.ts`: `adapter-static` with `200.html` fallback, `/api` proxied to `:8000` in dev; `src/routes/+layout.ts` sets `ssr = false`). Review screen in `src/routes/+page.svelte`, API client in `src/lib/api.ts`. Commands: `npm run dev`, `npm run check`, `npm run lint`, `npm test`.
- `api/` – FastAPI package `forglemmigej_api` (src layout, Python 3.13, `uv`). Commands: `uv run uvicorn forglemmigej_api.app:app --reload`, `uv run pytest`, `uv run ruff check .`, `uv run ruff format .`, `uv run alembic upgrade head`. Schema in `models.py` (SQLAlchemy 2), migrations in `api/migrations` (Alembic; non-native enum CHECK changes must be added by hand). Tests use a throwaway `forglemmigej_test` database on the local Postgres.
- Review flow: `scheduling.py` (models come from the `memory_models` registry: the champion (FSRS only) schedules from cached card state, challengers (FSRS or LightGBM) predict from the card's history in shadow mode; loaded models are cached per version and parameter digest; fuzzing off), `review.py` (next card: due first, then new words up to `new_words_per_day` (default 15; a word's second card, cloze or recall, does not count) in curriculum order; a second card unlocks once the word's recognition card reaches `review`; an answer logs the review, the typed text and the champion prediction computed *before* the update), `app.py` (`/api/next`, `/api/cards/{id}/answer`, `/api/sessions`, `/api/stats`).
- ML: `features.py` is the shared, point-in-time feature function (training and serving; refuses future reviews; FSRS replay cached per history prefix, shared with `scheduling.py`; the `fsrs_recall` feature uses pinned FSRS-6 default parameters, not the library defaults). `training/` (needs `uv run --group ml ...`): `dataset.py` (review log → examples; serving-side history loader), `public.py` + `build_public.py` (public fsrs-dataset logs in `data/raw/fsrs-dataset/` → `data/processed/public_examples.parquet`), `evaluate.py` (log loss, Brier, AUC, binned calibration, chronological split), `models.py` (logistic regression, LightGBM), `fit_fsrs.py` (fits FSRS to the learner's reviews and registers a challenger; needs the ml group, CPU-only PyTorch), `pretrain_lightgbm.py` (trains LightGBM on the public examples and, with `--register`, adds it as a shadow challenger; registry kind `lightgbm`, stored as LightGBM model text, predicted in the API via `scheduling.LightGbmModel`, so `lightgbm` is a runtime dependency), `gate.py` (the champion/challenger gate: per challenger, shadow predictions vs the champion on shared reviews a day+ apart; FSRS only, n ≥ 300, card-level bootstrap p ≥ 0.95 on log loss, calibration not worse; `promote()` retires the old champion, rebuilds card states, records `model_promotions`; CLI `--report` / `--promote VERSION --reason ...` for rollback), `nightly.py` (the nightly job: data summary, shadow evaluation of every model on reviews at least a day apart and on the same reviews, the gate, an FSRS fit once there are 1000+ reviews and no fitted challenger younger than 14 days, all logged to MLflow). Notebooks in `notebooks/` run with `uv run --project ../api --group ml jupyter nbconvert --execute --inplace <nb>`.
- `api/src/forglemmigej_api/content/` – importer: frequency list + Danish Wiktionary (kaikki.org) + Tatoeba exports in `data/raw/` (gitignored; `--download` fetches them) → word/phrase items, sentence items and cards. `uv run python -m forglemmigej_api.content.importer --words 500` (`--dry-run` prints the deck). Idempotent; prunes stale cards (suspends reviewed ones).
- `data/curation/` – `word_overrides.toml` (POS/lemma overrides, display fixes, meaning keys for example validation, excludes) and `survival_phrases.toml`.
- Containers: `api/Dockerfile` (build context = repo root; includes `data/curation`; default target `api`, `--target trainer` adds the ml group and runs the nightly job), `web/Dockerfile` + `web/nginx.conf` (static SPA, proxies `/api` to `http://api:8000`). `docker compose --profile app up --build` runs them locally on :8080 against a separate `forglemmigej_container` database.
- Deployment: `deploy/` (see `deploy/README.md`): `deploy/ansible/site.yml` prepares a fresh Debian 13 node (Tailscale + `tailscale serve` HTTPS, k3s with graceful shutdown, sudo rule, kubeconfig pointing at the Tailscale name); run it from WSL. Kustomize base in `deploy/k8s` (also MLflow 3.16.1 with SQLite on a PVC, UI via `kubectl -n forglemmigej port-forward svc/mlflow 5000:5000`; `nightly-training` CronJob at 19:30 Zurich), `deploy/deploy.sh user@node [--import-content]` (images tagged with the git commit, loaded into k3s over SSH). Grafana 12.2 at `/grafana/` (`grafana.yaml`; reads PostgreSQL as the read-only `grafana_reader`, created by its init container; dashboards as code in `deploy/k8s/dashboards/*.json`, provisioned read-only via a kustomize configMapGenerator; secret `forglemmigej-grafana` made by hand). `deploy/gate.sh report` / `deploy/gate.sh promote VERSION "why"` run the gate CLI as a one-off Job (rollback). The DB secret `forglemmigej-db` is created by hand, never committed.
- CI: `.github/workflows/` (`api`, `web`, `deploy`; path-filtered, actions pinned to commit SHAs, Dependabot for updates). Nothing is deployed from CI.
- Local preview: run the API against a throwaway database, `POSTGRES_DB=forglemmigej_preview uv run uvicorn forglemmigej_api.app:app --reload` in `api/` (create it and run `alembic upgrade head` with the same variable first), plus `npm run dev` in `web/`.
